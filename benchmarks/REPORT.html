note against Wine's Notepad

Wine's built-in Notepad is the Notepad-style reference that runs on this Linux box. Both programs ran in one Wine prefix, through the same translation layer, on the same virtual display (wine-9.0 (Ubuntu 9.0~repack-4build3), 1280x800x24). Times are medians of repeated runs (3 at no file, 3 at 1 MiB, 2 at 10 MiB, 1 at 100 MiB), and each program started from a fresh process. The 100 MiB figures are single runs, so they have no spread.

  • note (Windows build)
  • Wine's Notepad

At 100 MiB note opens the file in 0.4 s; Wine Notepad takes 107.7 s. Its 300-keystroke burst at 100 MiB had not settled after 300 s, so its CPU figure there is a lower bound.

Typing settled counts the bursts whose program went quiet within 300 s. A burst still busy at that point is a lower bound for its CPU figure, and the table shows how many of those there were.

What is and is not measured: both run under Wine's translation layer, not on native Windows. Wine's Notepad draws through a standard edit control, while note paints its own text through GDI, so the two have different costs. The note build here is MinGW, not MSVC. The CPU figure is the program's own user and system CPU time during a typing burst. Xvfb and xdotool run as separate processes and are not counted; Wine's code inside the program is.

Method and environment

  • Timed suites ran one at a time, after the builds finished. Each measurement repeats until it has at least five samples and 600 ms of total time, or at least three samples and ten seconds, or 200 samples, whichever comes first.
  • Repeatability: the same 1 MiB kernels, run twice, differed by up to 39%. Differences smaller than that spread are noise. The repeat was run only at 1 MiB, so the larger figures have no repeat evidence.
  • Medians are reported with the 10th and 90th percentiles where the spread matters. Per-keystroke numbers come from timing each call separately.
  • MB means 10⁶ bytes; MiB means 2²⁰ bytes. File sizes in the names are MiB: mixed-100m.txt is 100 MiB.
  • Heap figures come from a counting global allocator in a separate binary, one scenario per process. The timing runs use the normal allocator.
  • The SSE2 runs use a scratch copy whose dispatch reads NOTE_SIMD. The committed source is unchanged.
  • The Windows build is MinGW (x86_64-pc-windows-gnu), not MSVC. Its size and speed differ from the release binary's.
  • Colours follow the dataviz palette reference. In dark mode the three series colours pass every check. In light mode the aqua slot is 2.74:1 on the light surface, under the validator's 3:1 floor, so each chart that uses it also prints its values and has a data table. Status colours appear only as badges that carry an icon and a text label.
  • Not measured: native Windows, the Win32 renderer's frame times, real input latency through the window system, and the MSVC binary.
